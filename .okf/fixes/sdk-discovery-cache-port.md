# Symptom

Avowed (`Avowed-Win64-Shipping.exe`, unchanged since 2026-03-26) launched fine
through 2026-07-27, then on 2026-07-31 failed every launch with **three
different signatures across three runs** — on two different backend builds and
across a reboot:

1. Access violation in game code (wild pointer) during the first
   `BeginRenderViewFamily` FScene offset discovery.
2. `Failed to find FRenderTarget::GetDisplayGamma vtable index` → `Unknown
   exception in create_scene_capture (offset lookup)!` → scene-capture
   destroy/create churn → `Waiting for render target texture to be valid...`
   → game stops presenting → the 10-second `Last chance encountered for
   hooking` rehook loop until death.
3. Early hang ~2 s after inject, before UE scanning, no dump.

Nothing on disk had changed: game exe (March), NVIDIA driver (April), SteamVR
(Jul 22), profile config, PDAFWPlugin. Reboot did not help. SH2 and TOW2 kept
working on the same backends.

# Root cause

**A latent startup race in baseline UEVR discovery, not a regression from any
code or system change.** At every launch the SDK re-derives engine offsets by
disassembling live vtables — including entries UEVR has *already replaced with
its own hooks*: the failing GetDisplayGamma scan logged null-dereference
analysis at `7ffdce23…` addresses inside **UEVRBackend.dll itself**. Whether
discovery wins depends on ordering between hook installation and the scan.
This host won the race consistently for weeks, then started losing it
consistently; the environmental trigger was never isolated and the varied
signatures are the same race lost at different points.

# Fix (shipped, deployed backend `54c5f9d3…`)

Cherry-pick **two** commits from Joey's UESDK lineage onto the pinned baseline
`491f973a` (local submodule branch `cache-on-baseline`, tip `d9ee8a5`):

- `d92809c` "Cache validated UE startup discoveries" — FRenderTarget / FScene /
  FSceneView / FTexture / UTexture discoveries are fingerprint-validated
  against `%APPDATA%\UnrealVRMod\<exe>\cache\sdk_discovery.json` (module path,
  file size, PE `TimeDateStamp`) and reused instead of re-scanned; successful
  discoveries are written back, so every game self-seeds its own cache on its
  next good run.
- `29a0c2e` "Tighten cached startup scan logging" — logging only.

Avowed's profile already held a valid cache (fingerprint-matched, written by
an earlier build lineage); with the port, the log shows `Reused cached
FRenderTarget vtable indices` and the crashing scans never run. Scan activity
now ends ~11 s after inject with no further discovery for the rest of the
session.

# Rejected: the third cache commit (performance regression)

`0d78366` "Cache late UE 5.7 render discovery" (FSceneViewFamily /
FTextureRenderTargetResource / StereoStuff) was initially included and
**reverted**: its cache-hit check replaced baseline's run-once behavior, and
on Avowed (where the FSceneViewFamily entry does not cleanly hit) it re-ran
the full offset discovery **every frame** — 905 `Attempting to find offsets
for FSceneViewFamily` scans in one short session — producing severe
performance loss. This validates the standing rule: port from Joey's lineage
only the minimum needed; his commits bundle behavior changes beyond their
titles. See [narrow-port-scope](../decisions/narrow-port-scope.md).

# Secondary finds fixed in the same session

- **Shrunken/unscrollable UEVR menu ("why does this happen sometimes")**:
  ImGui persists menu window size keyed by the window *title*, which embeds
  the build tag. All locally built backends shared the degenerate identity
  `UEVR [no_tag+0-]` because the pre-build `MakeCommitHash.bat` early-exits
  when a stale `src/CommitHash.autogenerated` (empty hash, frozen build date
  "21.07.2026 10:32") already exists. The Avowed profile's `no_tag` entry had
  been accidentally resized to 363×355, making options unreachable. Fixed the
  saved state (700×700) and deleted the stale gitignored file so every future
  build self-identifies with its real tag/hash/date.
- Open ship item: the two cache commits exist **only in the local UESDK
  submodule** (`cache-on-baseline`); the superproject gitlink change is
  uncommitted, and the submodule's upstream is the gated UESDK fork — the pin
  must be pushed somewhere reachable before this checkpoint can be published.
